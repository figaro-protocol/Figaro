    Function validateCommitmentAgreement

    • validateCommitmentAgreement(
          agreement: Agreement,
          expectedHash: `0x${string}`,
          specs: SpecSource,
          commitment: Commitment,
          design: HydratedAssembly | null,
      ): { issues: CommitmentAgreementIssue[]; ok: boolean }

      The off-chain layer of the verification stack, run on BOTH sides of the bilateral commit (buyer before initiating, seller before counter-signing) so neither party signs an invalid agreement. Four checks: every present clause conforms to its clause spec (validateContent; process-log clauses are presence-markers, skipped); where a denomination pin is composed, the pin equals the token of the commitment about to be signed; the order carries every clause of the design its provenance names (the registered agreement's and the assembly-scoped ones) and every designer value (block.design.fills) the design sets arrives unchanged — design is the hydrated assembly the agreement's provenance names, null when none was read, and an agreement naming a design then fails (a buyer or a seller never drops a designed clause or changes a designer's value); and the checkoutHash about to be signed equals the merkle root recomputed from the clauses. The agreement's topology leaf is well formed, and present wherever a design is named (topologyIssues). Catches a malformed agreement before a chain round-trip.

      commitment is the commitment being signed. It alone carries the payment and the token: no clause restates either, so there is no copy across the two to compare.

      Parameters

      • agreement: Agreement
      • expectedHash: `0x${string}`
      • specs: SpecSource
      • commitment: Commitment
      • design: HydratedAssembly | null
