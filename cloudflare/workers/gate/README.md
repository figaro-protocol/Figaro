# Gate Worker

The front door. Validates access codes, mints sessions, hands off to the Pages-hosted Next.js app.

## State machine

```
incoming request
    │
    ▼
[has session cookie?]
    │
    ├─ yes ─► [session valid in KV?] ─ yes ─► forward to Pages
    │                                  no  ─► fall through
    │
    └─ no ──► [has ?code=… or POSTed code?]
                │
                ├─ yes ─► [code valid + unredeemed?]
                │              │
                │              ├─ yes ─► mark redeemed; mint session;
                │              │         set cookie; 302 to "/"
                │              │
                │              └─ no  ─► show error in form
                │
                └─ no  ─► serve access-code form
```

## KV schema

### `CODES` namespace

- **Key:** access-code string (e.g., `"k4n7q2pX"` — operator-chosen, opaque)
- **Value:** JSON
  ```json
  {
    "issuedAt": "2026-04-29T15:00:00Z",
    "note": "first beta participant",
    "redeemedAt": "2026-04-29T15:42:00Z"
  }
  ```

`redeemedAt` is set the first time the code is redeemed. Subsequent attempts return "already redeemed."

### `SESSIONS` namespace

- **Key:** session ID (UUIDv4, generated by the Worker)
- **Value:** JSON
  ```json
  {
    "code": "k4n7q2pX",
    "redeemedAt": "2026-04-29T15:42:00Z"
  }
  ```
- **TTL:** `SESSION_TTL_SECONDS` (default 30 days, renewed by no mechanism — when the TTL expires, the session is gone and the participant must redeem a fresh code)

## Operator commands

### Issue a code

```bash
wrangler kv:key put --namespace-id=<CODES_ID> "k4n7q2pX" '{"issuedAt":"2026-04-29","note":"alice"}'
```

Then send `https://<subdomain>.figaroprotocol.com/?code=k4n7q2pX` to the participant via your private channel.

### Revoke a session

```bash
wrangler kv:key delete --namespace-id=<SESSIONS_ID> "<session-id>"
```

To find a session ID, look it up by the participant's code:

```bash
wrangler kv:key list --namespace-id=<SESSIONS_ID> --prefix "" | jq '.[] | select(.metadata.code == "k4n7q2pX")'
```

(Worker doesn't store metadata yet — see "follow-ons" below.)

### Revoke a code (preventing redemption)

```bash
# If the code hasn't been redeemed yet, just delete the record.
wrangler kv:key delete --namespace-id=<CODES_ID> "k4n7q2pX"

# If the code HAS been redeemed and you want to additionally invalidate
# the session, delete from SESSIONS too.
```

## Local development

```bash
npm install
wrangler kv:namespace create CODES --preview
wrangler kv:namespace create SESSIONS --preview
# Paste preview IDs into wrangler.toml under `preview_id` for each binding.
wrangler dev
```

Visit `http://localhost:8787` to see the access-code form.

## Follow-ons (non-blocking for v1)

- Session metadata indexing (search SESSIONS by code) — currently O(n) scan via `wrangler kv:key list`.
- Code-issuance UI for the operator (currently CLI-only).
- Sliding TTL renewal on each session check (currently fixed-expiry).
- Rate limiting on the form (currently relies on CF's default DDoS protection).
